# FinScope data and report contract (schema 1.0.0)

The static demo is a deterministic **fictional scenario**. The workbench is research software, not a production trading system. Run `python -m finscope.cli demo --output web/data/report.json` to regenerate both 5 and 20 session reports and `data/demo/prices.csv` plus `data/demo/events.json`. `generated_at` changes per run; the experiment content, hashes and ordering remain deterministic for fixed dependencies and seed. The demo never uses Yahoo Finance data.

## Import inputs

Prices CSV has exactly these required columns: `date` (ISO `YYYY-MM-DD` U.S. trading session), `ticker` (1–16 ASCII letters, numbers, period, underscore or hyphen), `close` (finite and strictly positive), `volume` (finite and nonnegative). Additional columns are ignored. Duplicate ticker/date, invalid date or numeric data, empty rows and inputs over 250,000 rows fail. A close-to-close log change above 700 in magnitude is rejected before floating-point ratios can overflow; later non-representable portfolio metrics also fail clearly. Adjusted closes are required for economically meaningful returns; the engine cannot detect splits or dividends. Missing sessions are not interpolated. Each row is an observed close and may enter features for its own date, while the forward target starts with the following return.

Events JSON is an array of at most 25,000 objects. Each requires nonempty `id`, `ticker`, `kind` (`filing`, `social`, `supply`), `event_time`, `available_at`, `ingested_at`, `text`, and `source`. Times must be timezone-aware ISO strings and are normalized to UTC. `available_at` cannot precede `event_time`; event usability is `max(available_at, ingested_at)`. Event text is limited to 4,000 characters. IDs must be unique. Optional `revenue_growth` and `delay_days` are finite numbers, with `delay_days >= 0`; optional `relationship` is a ticker string. Supply and social fields are provided by the importer, not independently verified. A post's mutable likes or engagement totals are never backfilled into older feature rows. Repeated normalized social text is counted once within each 30 day as-of window.

This version supports **U.S. listed-equity daily adjusted closes**. The decision is formed *after the actual exchange close* for the supplied session, including scheduled early closes. The close price is observed then. Event information has a separate, deliberately early **16:00 UTC cutoff**, before both regular U.S. closes and the supported 13:00 Eastern scheduled early closes (17:00 UTC in daylight saving time). Only an event whose `max(available_at, ingested_at)` is at or before 16:00 UTC can enter that date's features. Events arriving after 16:00 UTC are deferred even if they were available before that day's actual close; the model sacrifices some same-day information to make this timestamp policy safe without an exchange calendar. The cutoff is **not** the exchange close or the decision time. Non-U.S. markets, intraday closes and unusual/unscheduled close times require a market-calendar adapter and are outside this contract. An importer must supply truthful historical ingestion timestamps. Running today against a cached old file, even with an old `available_at`, does not prove the file was available to a researcher at that historical time. Import reports explicitly mark the point-in-time claim as unverified.

## Experiment method

`run_experiment(prices, events, horizon=5, seed=42) -> dict` supports horizons 5 and 20. The CLI's `run --prices FILE --events FILE --output FILE --horizon 5` accepts local files; it does not fetch market prices. The target is the standard deviation of the next `horizon` ticker close-to-close log returns, annualized by `sqrt(252)`. The last label date is recorded per row. The shared chronological rolling splits use 360 training, 80 calibration and 20 step sessions for a long dataset, or 120/40/20 for compact datasets. A full horizon gap follows each training and calibration stage; the code also checks actual ticker-specific `label_end` against the next stage start. The same rows and dates evaluate every model. Refit cadence, `Ridge(alpha=20)`, imputing, scaling, feature groups, and 90% residual interval calibration are fixed before test evaluation. Imputer and scaler fit on training rows only. Interval coverage is an empirical diagnostic; it has no guarantee under drift.

Models are `historical_volatility` (past 20-return volatility), `price`, `price_filing`, `price_filing_alternative`, and `freshness_fusion`. The `volume_change_20` feature uses an as-of `log1p(current volume) - log1p(past 20-session median volume)` ratio, mapped back with `expm1` and capped at 1,000 to prevent finite extreme inputs from overflowing; a zero past median gives a missing feature. The filing text change uses pairwise TF-IDF cosine distance between the two most recent usable filings, so there is no future-fitted corpus vocabulary. The alternative event signal is a small disclosed positive/negative lexicon, **not a learned sentiment classifier** or reliable investment signal. Freshness is an exponentially decayed age feature. Input PSI uses training-fitted quantile bins; 0.10 and 0.25 are heuristic discussion thresholds, not statistical tests. `mean_input_psi` is a full retrospective experiment aggregate, not an as-of value at a chart date. Every predetermined ablation remains in the report regardless of result. No Qlib run, learned graph neural network, DoubleAdapt reproduction, order-book execution or LLM sentiment model is claimed.

The strategy is a descriptive long/cash volatility target, `min(1, 0.2 / max(prediction, 1e-6))`. A forecast formed after actual close `t` cannot affect the return into close `t+1`: its first possible return is close `t+1` to close `t+2` (two series indices). Entry, exits and changes cost 10 basis points times absolute position change, including initial entry. Cash and risk-free return are zero. For a different cost input, recompute each row as `net_return = gross_return - turnover * cost_bps / 10000`; portfolio daily return and daily turnover are the arithmetic means across the same fixed number of ticker sleeves every date. The per-date series preserves gross return, turnover, position and net return for this calculation. Multi-ticker portfolios require an observed evaluation row for every ticker on every common test date. A missing ticker/date in that evaluation panel raises an error instead of silently changing weights; missing sessions outside it are not interpolated. Single-ticker imports can omit market holidays. Synthetic backtest metrics are scenario diagnostics, **not evidence of tradable alpha**. Repeated holdout reuse, data revision, universe survivorship, non-stationarity and imperfect execution remain limitations.

## `web/data/report.json`

The root object is versioned and has the following required members:

| Key | Shape and meaning |
| --- | --- |
| `schema_version` | String `1.0.0`. |
| `provenance` | `data_kind` (`synthetic` or `user_import`), `dataset_sha256`, UTC `generated_at`, `seed`, `package_versions`, `availability_claim`. |
| `config` | Horizon or demo `horizons`; annualization, train/calibration/step sessions, ridge alpha, nominal interval coverage, default cost basis points, target volatility, execution lag closes, `event_information_cutoff_utc`, `market_scope`, `decision_time`, `portfolio_weight_policy`, and fixed `model_order`. |
| `companies` | Array of `ticker`, `name`, `sector`, `fictional`. Fictional names are never attached to real inputs. |
| `experiments` | Object keyed by horizon string (`"5"`, `"20"`). Each value has `horizon`, shared `observations`, and `models`. |
| `evidence` | Array of input events with source, text and all three original timestamps plus computed `usable_at`; optional selected numeric/relationship fields. Demo content is authored fiction. |
| `audit` | Warning strings, price/event row counts, `quality` counters (`ticker_sessions`, `missing_ticker_dates`, `zero_volume_rows`, `event_after_last_information_cutoff`), PSI heuristic thresholds, and split boundaries (`splits` for one horizon or `splits_by_horizon` for demo). The legacy `event_usable_after_last_close` duplicates the cutoff count for schema-1 consumers; its name does not mean exchange-close time. |
| `network` | `kind: descriptive_supplied_relationships`, and `{source,target}` edges from supplied events; no learned GNN. |

Each `experiments[horizon].observations` row contains `date`, `ticker`, `close`, `actual` forward realized volatility, nullable `past_volatility`, and `label_end`. This shared array appears once per horizon. Join it to any model series by `(date, ticker)`; ordering is identical.

Each `experiments[horizon].models[model_name]` contains:

- `features`: explicit input feature names.
- `forecast_metrics`: `count`, `mae`, `rmse`, `bias`, `coverage`, `mean_interval_width` (volatility units; annualized decimal).
- `strategy_metrics`: `total_return`, `annualized_volatility`, `sharpe_zero_cash_rate`, `maximum_drawdown`, `mean_daily_turnover`.
- `regime_errors`: `low_past_vol`, `medium_past_vol`, `high_past_vol`, each with `count` and `mae` (null if empty). Regimes use past volatility thresholds 0.15 and 0.30.
- `rolling_error`: `{end,mae}` records; `mean_input_psi`: mean across rolling windows and active features.
- `series`: sorted records with `date`, `ticker`, `prediction`, `lower`, `upper`, `position`, `turnover`, `gross_return`, `net_return`. All numeric JSON values are finite; nullable unavailable values in shared observations are JSON null.

Demo `audit.splits_by_horizon[horizon]` is a list of `train_start`, `train_last_origin`, `train_last_label_end`, `calibration_start`, `calibration_last_origin`, `calibration_last_label_end`, `test_start`, and `test_end`. The two strict inequalities are `train_last_label_end < calibration_start` and `calibration_last_label_end < test_start`.

## Separate `web/data/sec.json`

`python -m finscope.cli sec --output web/data/sec.json --user-agent 'Researcher Name researcher@example.org'` fetches official SEC CompanyFacts for AAPL, MSFT and NVDA with an identifying User-Agent, HTTPS verification, 20 second timeout, three bounded attempts, 0.25 second minimum interval and local raw JSON cache under ignored `local-data/sec/`. It records `url`, `raw_sha256`, `retrieved_at` and per-company selected `revenue`, `net_income`, `assets` facts. Each selected fact retains `tag`, `taxonomy`, `unit`, `value`, `start` (null for instant concepts), `end`, `filed`, `accession`, `accession_url`, form and fiscal metadata. Annual duration requires 330–400 days and a 10-K/10-K/A. Selection enforces `filed <= as_of` and favors the newest period, then latest eligible filing/restatement. EdgarTools optionally executes a separate real CompanyFacts parse check and records version/count or the reason it could not run; it is not the selection implementation. The SEC artifact contains no synthetic prices, forecasts or scores. A current fetch with an historical as-of filter cannot certify a historically archived raw snapshot.
